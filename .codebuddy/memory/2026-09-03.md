## 修复 mkdocs 文档站渲染问题（docs/ 目录）

背景：`docs/` 是 `mkdocs new docs` 生成的站点，素材由 Typora 编写（`docs/docs/*.md` + 同名 `.assets/` 图片目录）。

发现并修复的两类问题：

1. **代码块原样显示 ```bash**（共 243 处缩进围栏 + 3 处开闭围栏缩进不一致）
   - 根因：python-markdown 的 `fenced_code` 正则要求围栏顶格（`^`），缩进后不识别；
     `pymdownx.superfences` 可识别缩进围栏，但**同一列表项内正文与围栏缩进必须一致**，否则整体失效退化成普通缩进代码块。
   - 处理：`mkdocs.yml` 增加 `markdown_extensions: - pymdownx.superfences`；
     并按列表项结构统一缩进（正文行与围栏一起挪到 `target = max(4, 正文缩进, 围栏缩进)`，
     使代码块保留在列表项内、有序列表编号不中断）；非列表上下文的缩进围栏取消缩回到第 0 列。

2. **46 张图片 404**
   - 根因：这些图片用的是裸 HTML `<img src="./xxx.assets/a.png">`。mkdocs 只重写 markdown 语法
     （`![](...)`）的相对路径，裸 HTML 不动；而 `use_directory_urls` 让页面位于 `/<页面名>/` 下，
     `./` 解析到了错误目录。
   - 处理：全部转成 `![alt](src)`（顺带把 URL 编码的中文路径还原成真实中文文件名），
     原先的 `style="zoom:NN%"` 被去掉（readthedocs 主题有 `img{max-width:100%}`，图片不会溢出）。

验证方式（可复用）：`mkdocs build --strict` 无告警；生成页面里
`<pre><code>``` 数量为 0（未渲染的围栏）；按页面 URL 解析 `img src` 后 404 图片数为 0。

新增 `docs/requirements.txt`（mkdocs + pymdown-extensions，pymdown-extensions 为本次新增依赖）。
